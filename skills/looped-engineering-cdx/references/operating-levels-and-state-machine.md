# Operating Levels and State Machine

This file is authoritative for operating levels, lifecycle state transitions, transition rules, and per-state artifacts.

Use the lightest operating level that satisfies the task, then upgrade or downgrade when evidence changes. The lifecycle vocabulary remains Intake, Orient, Judgement, Research, Architecture, Plan, Plan Review, Execute, Verify, Drift/Health/Invariant, Reflect, Commit/Handoff, Alert, and Continue/Stop.

## Operating Levels

| Level | Use when | Required gates | Optional gates | Artifacts | Validation depth | Alert expectations |
| --- | --- | --- | --- | --- | --- | --- |
| Lite | Answer-only work, small edits, simple bug fixes, or explicitly invoked `looped-engineering-cdx` work whose requirements are clear and blast radius is low. | Intake, Orient, Execute when editing, Verify, Alert. | Judgement, Research, Architecture, Plan, Plan Review, Drift/Health/Invariant, Handoff when risk appears. | Working-memory note; changed-files and validation evidence when files change. | Targeted command or manual check relevant to the touched file; broader validation only if shared behavior is affected. | Send an alert on finish or observed stop when the workflow was explicitly invoked or long-running. |
| Standard | Clear multi-file features, normal refactors, repository maintenance, dependency updates with known behavior, and plan execution with bounded risk. | Intake, Orient, Plan or plan delta, Execute, Verify, Reflect, Alert. | Repository memory search, Architecture, Plan Review, triggered governance gates, Handoff when risk or scope warrants. | Concise plan or plan delta, tests per task, validation evidence, changed-files evidence, risk notes, Knowledge Gap Gate, Architecture Fitness Gate, or Success Metrics Gate notes when triggered. | Targeted tests plus lint/typecheck/build or broader tests when shared behavior changes. | Send an alert on finish, blocker, validation failure, or handoff. |
| Full OS | Fuzzy, high-impact, contradictory, architecture-changing, migration/data semantics, security/data-loss/accessibility, AI/ML or research-system, long-running, handoff-heavy, or multi-milestone work. | Intake, Orient, Judgement when fuzzy or high-impact, repository memory search, Architecture when structural, formal Plan, Plan Review, Execute, Verify, Drift/Health/Invariant, Reflect, Commit/Handoff, Alert. | Specialist research, current docs, consensus roles, repository memory writeback, context compression. | Formal plan, review result, ADR/risk/assumption/debt/health, Knowledge Gap Tracker, Architecture Fitness Functions, and Success Metrics artifacts as triggered, context snapshot, rollback plan for non-trivial change, handoff or milestone report. | Targeted and broader validation, build/typecheck/lint when available, reproducibility checks for research or AI/ML, graph/index freshness only when repository rules require it. | Alert on each milestone finish, observed stop, blocker, unresolved validation, handoff, or human decision. |

## Standard Planning Trigger Table

| Trigger | Selected level | Planning requirement | Plan review requirement | Validation expectation |
| --- | --- | --- | --- | --- |
| Ordinary clear multi-file feature or normal refactor | Standard | Concise plan or plan delta required. | No `plan-review-cdx` unless risk escalates. | Targeted validation plus broader checks only where shared behavior changed. |
| Bounded Standard with formal review: clear public API addition with stable semantics, clear dependency change, clear cross-module shared behavior, or elevated but locally testable validation risk | Standard | Formal plan required. | `plan-review-cdx` required before execution. | Targeted validation plus relevant integration, lint, typecheck, or build checks. |
| Mandatory Full OS escalation: migration/data semantics changes, irreversible actions, security/data-loss/accessibility impact, unclear acceptance criteria, fuzzy or contradictory goals, high-impact work, architecture-changing work, long-running milestones, handoff-heavy work, AI/ML or research systems, or multi-milestone tasks | Full OS | Formal plan and governance gates required as triggered. | `plan-review-cdx` and required consensus roles before implementation. | Broad validation, rollback evidence, closeout evidence, and memory writeback as applicable. |

If both Standard and Full OS triggers apply, choose Full OS. If Full OS triggers apply during Standard work, upgrade immediately before committing to the risky design.

## Transition Table

| State | Entry criteria | Required actions | Required artifacts | Exit criteria | Allowed next states | Escalation/stop triggers |
| --- | --- | --- | --- | --- | --- | --- |
| Intake | New user request, resumed handoff, or plan execution request. | Classify task, estimate blast radius, select provisional operating level, identify irreversible or high-risk decisions. | Operating-level note; explicit assumptions for ambiguous scope. | Task type, blast radius, and lightest sufficient level are known. | Orient, Judgement, Continue/Stop. | Stop for missing required human decision, destructive request ambiguity, or credentials/secrets. Upgrade for fuzzy, high-impact, or multi-milestone scope. |
| Orient | Intake selected a workable level. | Read repository instructions, relevant specs/plans/tests, current state, and required skill references. For Standard or Full OS, check available repository memory sources. | Context package scaled to level; unavailable-memory note when applicable. | Relevant files, constraints, validation commands, and repository rules are known or confirmed absent. | Judgement, Research, Architecture, Plan, Execute. | Upgrade if context contradicts the request, acceptance criteria are unclear, or architecture/data/security risk appears. |
| Judgement | Goal is fuzzy, incomplete, contradictory, high-impact, hidden-assumption driven, or drifting. | Use `judgement-engineering-cdx` or inline judgement review; list options, assumptions, reversibility, risks, success signals. | Judgement brief or provisional interpretation. | A reversible path is selected or a human decision is requested. | Research, Architecture, Plan, Continue/Stop. | Stop for high/critical unresolved decision; upgrade to Full OS if not already selected. |
| Research | Current facts, docs, product behavior, academic sources, or solution options are uncertain. | Route to the most specific research/documentation skill; capture source and date for unstable facts. | Research note, current-doc citation, or source summary. | Required external facts are verified or uncertainty is documented. | Architecture, Plan, Execute, Judgement. | Stop for policy/data decision or unverifiable high-impact claim. |
| Architecture | Structure, coupling, API boundaries, migration shape, dependency choice, or maintainability is central. | Review dependency evidence, ADRs, impact analysis, boundaries, testability, and drift. Use Architecture reviewer when required. Define triggered Architecture Fitness Gate checks where practical. | Architecture review note; ADR draft when required; Architecture Fitness Functions when triggered. | Boundary and design direction are clear enough to plan, and triggered fitness checks have pass/fail action. | Plan, Plan Review, Judgement. | Stop for high/critical reviewer conflict; upgrade for public API, migration, data semantics, or broad coupling changes. |
| Plan | Work is Standard or Full OS, or Lite risk escalated. | Draft a plan or plan delta with files, tasks, tests, commands, risks, assumptions, and expected outcomes. Resolve, accept, or convert triggered Knowledge Gap Gate items into experiments. Record triggered Success Metrics Gate metrics, targets/direction, measurement method, and closeout evidence location. | Concise plan, plan delta, or formal plan based on level; Knowledge Gap Tracker or Success Metrics notes when triggered. | Plan is actionable, validation path is known, triggered knowledge gaps are closed, and triggered success metrics are measurable. | Plan Review, Execute, Research, Architecture. | Upgrade if plan reveals broader blast radius, unclear acceptance criteria, or triggered governance gates. |
| Plan Review | Formal review is triggered by Full OS or bounded Standard risk. | Run `plan-review-cdx` or required reviewer roles; resolve medium/high/critical findings or record accepted risk. | Plan review result and resolved findings. | Required reviewers are pass or pass-with-notes, with no unresolved medium/high/critical finding. | Execute, Plan, Judgement, Continue/Stop. | Stop for high/critical conflict, human-decision status, or unresolved validation strategy. |
| Execute | Plan, plan delta, or clear Lite edit is ready. | Work in vertical slices; use TDD when behavior changes; edit smallest scope; keep changed-files evidence current. | Code/content changes; tests or validation notes per slice. | Slice complete and targeted validation run. | Verify, Plan, Architecture, Judgement. | Upgrade for unexpected shared behavior, new dependency, public API change, migration/data risk, or failing tests with unclear root cause. |
| Verify | A slice or milestone changed files or behavior. | Run targeted tests, broader suites when needed, lint/typecheck/build when available, graph/index freshness only when required, applicable fitness checks, and triggered Success Metrics measurement. | Verification note with commands, results, failures, residual risk, Architecture Fitness Gate evidence, and Success Metrics evidence when triggered. | Required validation passes or failures are classified, applicable fitness checks are handled, and triggered metrics are measured or classified. | Drift/Health/Invariant, Reflect, Execute, Continue/Stop. | Stop for unresolved local validation failure, failed fitness check without acceptable action, blocker, or human decision required. |
| Drift/Health/Invariant | Standard shared behavior changed, Full OS milestone is closing, or invariants are triggered. | Check invariants, drift, health, risk, assumptions, unresolved knowledge gaps, failed fitness checks, unmet success metrics, rollback, telemetry, and memory writeback duties. | Health/drift/invariant evidence as triggered; Knowledge Gap Gate, Architecture Fitness Gate, and Success Metrics Gate status when triggered; context snapshot for Full OS milestones. | Severe drift is resolved or blocked; minor drift, unresolved gaps, failed fitness checks, or unmet success metrics have linked follow-up or accepted status. | Reflect, Execute, Plan, Continue/Stop. | Stop for severe drift, invariant failure, unresolved important gap, failed fitness check, unmet success metric, or rollback gap that cannot be corrected locally. |
| Reflect | Verification is complete or a milestone is nearing close. | Review coupling, architecture depth, repeated concepts, mocks, interface complexity, and follow-up needs. | Reflection note or milestone retrospective when appropriate. | Residual risks and follow-ups are recorded. | Commit/Handoff, Alert, Execute. | Upgrade if reflection reveals architecture drift or unresolved governance gap. |
| Commit/Handoff | Work is complete, paused, or transferring. | Detect unexpected changes; stage only if committing was requested; write handoff when pausing, closing Full OS milestone, or context pressure is high. | Changed-files summary, commit summary if requested, or handoff with resume context. | Another agent can resume without raw chat history, or no handoff is needed for Lite/Standard closeout. | Alert, Continue/Stop. | Stop for unrelated changes that make intended change unsafe to separate, or missing user approval for commit/push. |
| Alert | Finish, observed stop, blocker, validation failure, handoff, or human decision occurs. | Send `alert-me` notification with concise status. | Alert outcome evidence. | Notification sent or failure recorded. | Continue/Stop. | Use fallback notification if sender is unavailable; record alert failure if fallback also fails. |
| Continue/Stop | Workflow completed, paused, blocked, or redirected. | Decide whether another slice is required; if stopped, leave state note and alert. | Final summary, handoff, or blocker note. | No required work remains, or a real stop condition is reached. | Intake, Orient, Execute, Stop. | Stop for explicit user pause, unresolved human decision, blocker, missing secret, destructive ambiguity, or validation failure. |

## Upgrade Rules

- Upgrade Lite to Standard when the work becomes multi-file, shared behavior changes, validation requires more than a local check, or repository rules require a plan.
- Upgrade Lite or Standard to Full OS when any mandatory Full OS escalation trigger appears: migration/data semantics, irreversible action, security/data-loss/accessibility impact, unclear acceptance criteria, fuzzy or contradictory goals, high-impact architecture work, long-running milestone, handoff-heavy work, AI/ML or research system, or multi-milestone scope.
- Upgrade when reviewers disagree on medium-or-higher risk, when unexpected dependencies appear, or when validation failures reveal unknown root cause.
- Apply the stricter gate immediately after upgrade; do not continue implementation under the prior level.

## Downgrade Rules

- Downgrade Full OS to Standard only after uncertainty is resolved, no Full OS trigger remains, required high/critical risks are mitigated, and the remaining work is bounded and locally testable.
- Downgrade Standard to Lite only when orientation shows a single-file or answer-only task with clear behavior and low blast radius.
- Do not downgrade to avoid plan review, ADR, rollback, or validation obligations that were already triggered by completed decisions.
- Record downgrade rationale in working memory, the plan delta, or the handoff.
