# Academic search and acquisition

Run `~/anaconda3/bin/python ~/.codex/skills/lit-search-cdx/scripts/lit_search.py` with the operation below. Read [the interface reference](references/interface.md) for arguments, record fields, recovery, fixtures and credential setup.

1. Run `doctor`; use `doctor --live` when current account diagnostics are needed.
2. Choose one parent run ID and persist it in the review plan. Pass `--run-id` to every operation across workers, queries, survey topic runs and resumes. Standalone commands generate an ID when omitted; reuse the returned ID to resume. Never create another ID to bypass the 100-request run cap.
3. Use `search QUERY --run-id ID` for Scholar discovery. Use `--provider openalex` for requested supplementary discovery or an identified coverage gap. Record supplementary arXiv, Semantic Scholar and venue searches with source provenance in the same record format.
4. Use `enrich --input candidates.json --run-id ID` for existing Zotero metadata and OpenAlex DOI resolution. Unknown identities remain unresolved. Search snippets are not abstracts. Merge exact DOI or canonical arXiv matches only; flag title/author similarities for triage.
5. Use `citations SEED` for one-hop forward or backward traversal and `versions CLUSTER` for Scholar versions. Scholar cites IDs, clusters and citation-export IDs are distinct strings. Default traversal limit is 20 per seed.
6. Present candidates or apply the parent review's approved triage criteria. Only then run `fetch --input selected.json --select ID ... --run-id RUN`. It tries existing Zotero attachments, direct PDFs, then keyed OpenAlex cached content. Known mismatches are rejected and uncertain files stay quarantined.
7. After actual user selection approval, run `import --input fetched.json --select ID ... --collection KEY_OR_EXACT_PATH --selection-approved --run-id RUN`. The target collection must be explicit and approved. Add `--create-collection` only for an approved missing top-level name; no implicit nested creation. Use `--dry-run` instead of `--selection-approved` for a preview. Existing selection approval authorizes import without a second confirmation.
8. Supervise the import with the [dialog-handling procedure](references/interface.md#dialog-handling-during-codex-runs). Informational dialogs should not leave the workflow waiting for the user; inspect and dismiss them when safe, and continue independent work if an affected import cannot proceed.
9. Review returned keys, collection actions, attachment states and remaining work. Import preserves existing metadata, tags, notes, files and memberships, adding the target membership and missing verified PDFs. Complete references without PDFs may import, with attachment gaps reported. Verify actual available PDFs and collection membership before handing items to the summarizer; metadata-only imports stay outside the PDF summarization queue.
10. Keep manual bundles as an explicit fallback. Run `bundle` on fetched JSON and selected IDs, and give the user `library.bib` beside `pdfs/`. Wait for manual-import confirmation only for this fallback, then verify item keys and actual attachments through `cli-anything-zotero --json items -c COLLECTION` and `attachments KEY`.

Import uses the existing server-bound Zotero local API authorization. Missing authority, ambiguous identities, changed items or uncertain attachment state block affected work. Preserve the journal, selected input, collection, state directory and run ID when resuming; successful earlier records remain imported. Zotero assigns new keys; durable UUID markers recover lost create responses. If an uncertain create has no exact compatible marker match, stop for review without repeating the create. New collections can retain a temporary marker name after interruption; resume renames only the saved collection key to its approved name. Do not retry by deleting the journal or blindly creating replacements. Read the interface reference for recovery and the external-writer race limitation.

Use `--output FILE` for normalized JSON and `--report FILE` for readable vault reports. Preserve completed queries, remaining work, source identifiers, citation counts by provider and retrieval provenance. `partial` or `blocked` is incomplete coverage, even when enough papers were found for a count target.

The shared SQLite ledger reserves before each outbound SearchAPI request, including retries, pages, citing searches, versions and citation export. It enforces 100 per parent run, the lower of 10,000 and actual account allowance, a frozen UTC daily allocation, and hourly availability. No billing dates means no metered Scholar request. OpenAlex never adds prepaid funds to its free allowance; unavailable free-budget information blocks charged operations. Single-entity metadata remains free. Cache lasts seven days; completed per-run steps persist beyond that. `--refresh` is an explicit new charged request.

Credentials use macOS Keychain service `lit-search-cdx`, accounts `searchapi` and optionally `openalex`. SearchAPI may fall back to the owner-only `~/etc/search_api.env`. Never print, source, or put keys in arguments. Authentication failures stop the provider. `auth import` refreshes SearchAPI Keychain from the protected file. Zotero write authorization is separate from these search-provider credentials. Browser retrieval and librarian maintenance remain outside this skill.

Scholar author lists marked with an ellipsis are incomplete. Bundling leaves those entries unresolved until verified OpenAlex or Zotero metadata supplies the authors.
